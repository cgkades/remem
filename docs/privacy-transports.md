# Memory transport and source controls

ReMem's core default uses local feature-hash embeddings; capture, canonical evidence admission and optional model proposals are disabled until explicitly configured. Managed/external `remem init` selects local BGE embeddings with hash fallback. Enabling capture does not silently enable assistant/tool evidence or local model proposals. Setup reports source modes, transport boundaries, retention and disable/forget controls without printing source bodies or credentials.

| Path                                                      | Actual transport and control                                                                                                                                                                                                                                              |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Filesystem provider and feature hash                      | Read configured local files and compute locally. Excluded paths and configured scopes remain enforced. Whole documents are screened before excerpts/catalog projection.                                                                                                   |
| Managed PostgreSQL                                        | The managed compose configuration binds a loopback port. Memory is sent to the explicitly configured database. An externally configured database can be remote; local-first is not a prohibition on explicit external storage.                                            |
| Local BGE embeddings                                      | Initial public model asset download can use HTTPS/proxy; embedding input stays in the local runtime. Hash fallback works without those assets.                                                                                                                            |
| Optional local learning model                             | Disabled by default. The operator supplies an absolute local asset directory. The isolated worker requires local files, prohibits remote model loading and has no hosted inference fallback. Explicit preparation downloads public weights, without session/memory input. |
| Native OpenCode/Pi answer model                           | Hosts can send ReMem's injected catalog/recall/history to their configured model. ReMem cannot promise an offline conversation when the host uses a remote model. Configure the host accordingly.                                                                         |
| Explicit providers or custom embedding/synthesis adapters | These are operator-configured extension boundaries. Their transport must be assessed separately; the core cannot guarantee an arbitrary plugin's network behavior.                                                                                                        |
| Debug logs                                                | Retrieval logs contain numeric counts, status and timing, without prompt/topic/source bodies. Unsafe source/error details are withheld.                                                                                                                                   |

The transport regression instruments fetch, TCP connection creation and DNS during configured filesystem/hash recall, explicit search/history and disabled learning. It establishes that tested core path, not every possible host/provider extension. Actual offline proposal inference and PostgreSQL/native gates are separately required. Asset installation and model download traffic are not claims of remote memory inference.

## Retained sources and scope

User capture requires explicit `capture.enabled`; canonical evidence requires `evidenceAdmission.enabled` and configured origins. Local proposals additionally require `learningModel.enabled`, an explicit model directory and a primary PostgreSQL provider. Preserve opt-outs on upgrade. Disable the respective modes in configuration to stop future capture/inference; this does not erase existing data. Provider/project/session identity and full source reconstruction gate eligible learning. OpenCode v1 has no trustworthy completed tool-evidence contract; native v2 and Pi evidence coverage is described in [host evidence learning](host-evidence-learning.md).

Retention is capacity based, with provisional defaults of 1 GiB soft and 2 GiB hard per provider/project. Compaction can shorten bulk/narrative evidence and ultimately remove older rows. There is no automatic age purge. The 24-hour extraction window is eligibility for model input, not database erasure. Missing or shortened evidence cannot authorize a new verified conclusion.

## Explicit historical search

All three supported native hosts expose `memory_history(query, provider?)`. It calls only providers advertising episodic history, in the caller's current project and selected provider. It queries at most four providers, returns at most five matches within an 800-token rendered response, caps the query at 2,000 characters and omits adjacent events. Roles, origins, session identity and timestamps stay visible. User hypotheses, assistant statements and failed tool results are historical observations, not verified current-state conclusions. Empty or partial results do not prove prior work never happened. Query more specifically when limits are reported.

This tool does not broaden capture defaults or authorize promotion. General operator episode search retains its existing scope; host disclosure requests whole-source screening before database response truncation. Full semantic bodies, metadata, provenance and recognition aliases are screened before native recall/catalog disclosure. Accessors, custom serialization objects, excessive nesting, credential patterns and known instruction-poisoning shapes are withheld. That conservative screen can omit benign content, and does not detect every secret or prompt injection. The trusted host instruction still treats every recalled source as untrusted data that cannot authorize tools, secrets or policy changes.

Timeout and cancellation bound caller waiting. Historical search is read-only; the PostgreSQL episode interface does not currently cancel an already-issued server query, which can finish within its database timeout after a caller abandons it. No late result is disclosed after cancellation. Local generation cancellation terminates its worker.

## Forgetting and backups

Episode forgetting requires a scoped preview and explicit confirmation. It removes the identified episode and directly associated candidates, retains body-free tombstones and rejects replay. It does not automatically delete separately reviewed semantic memories, their embeddings/catalog/source rows, or independently supported claims. Semantic deletion needs separate authorization; do not present episode forgetting as complete derived-memory erasure. Ordinary retention is not privacy forgetting.

Offline backups can contain forgotten bodies until the operator expires/removes them. Same-database restore reapplies local tombstones to suppress forgotten episodes/candidates. A new database does not inherit suppression automatically. See [privacy forget](privacy-forget.md) for commands and restore limitations.
