# Recovery of interrupted automatic capture

With capture, automatic promotion and canonical evidence admission enabled, each host's initialization attempts one bounded recovery batch for its current project. The shared capture coordinator and optional observation-store capability keep this behavior independent of OpenCode or Pi. Disabled modes and stores without the capability do nothing.

PostgreSQL selects at most eight already-approved canonical candidates with the current automatic policy version and outcome. It reuses the atomic consolidation pipeline: evidence, scope, conflicts and age are rechecked before semantic commit. Pending reviews, legacy approvals, unknown policy versions and other projects/providers are excluded. Concurrent restarts reuse the existing scope lock and processed ledger. Repeated recovery cannot write an old candidate over an edited or superseded memory.

Initialization waits only within the existing capture deadline so successful recovery is available before the first dispatch. Infrastructure errors or timeouts keep the host usable, report content-free diagnostics and abort the attempt. The coordinator tries once per initialization, with no new daemon or unbounded retry loop. Shutdown includes in-flight recovery within its existing deadline. PostgreSQL checks the abort signal after its bounded selection and the managed transaction checks it before semantic commit; a late query result cannot authorize promotion after cancellation.

This approved-candidate path covers interruption after automatic approval was persisted and before its first atomic promotion. Existing CLI consolidation-run recovery remains responsible for its `consolidating` claims.

## Retained evidence before extraction

OpenCode v2 and Pi additionally attempt one bounded retained-evidence batch during initialization and session shutdown. Both canonical evidence admission and semantic capture must be explicitly enabled. The coordinator reuses its existing lifecycle, deterministic extractor, native procedure verifier, server learning policy and atomic consolidation pipeline. It does not run a scheduler or infer new model conclusions.

Migration 0017 stores content-free extraction versions, attempts and thirty-second leases on retained canonical events. At most eight recent events from the current provider, project, host and currently enabled origins are claimed with `SKIP LOCKED`. Only user/tool evidence from the last twenty-four hours is considered. Already-linked candidate sources, forgotten evidence and active leases are excluded. Admission, original source identity/hash, canonical availability, scope, policy and conflicts are rechecked. Original user assertions retain user attribution; a supported native procedure retains its complete host-observed proof. Unsupported tool claims remain historical evidence. Conflicts, high-impact statements and model conclusions do not gain automatic authority.

The attempt deadline is the smaller of five seconds and the configured provider deadline (with a 100 ms floor). SQL mutation statements also have a one-second limit and abort checks before commit. Failed attempts leave their lease for retry after thirty seconds; later initialization or shutdown makes another bounded attempt. A backlog may need multiple sessions, and a recently interrupted lease may not recover at the next immediate startup. `memory_status.reflection` reports scoped recent unprocessed/claimed counts without source bodies; these counts include nonsignificant and currently disabled origins and are not a promise of eligible promotions.

Capture disabled means no retained-source extraction. Review mode creates pending candidates and does not promote them; later enabling automatic mode cannot override an existing pending review. Events never delivered by the host, evidence that was never persisted, or expired/forgotten sources cannot be reconstructed. This adds no durable host outbox. Separately reviewed semantic forgetting still has the documented independent confirmation boundary.

Acceptance is exercised by `tests/evidence-reflection.integration.test.ts`, lifecycle unit tests and the real native Pi/PostgreSQL learning gate. A native Session A with capture explicitly disabled retains four proof records and no candidates; fresh B explicitly enables capture, recovers one procedure before its first response and recalls it without A callbacks/transcript. This gate uses a deterministic driver/reader and does not evaluate model answer quality. Verification status and numerical evidence are recorded in the development checkpoint.

`tests/capture.test.ts` verifies one attempt, disabled modes, deadline cancellation, shutdown and continued capture after failure. `tests/learning-policy.integration.test.ts` verifies current-project selection, concurrent attempts, pending/foreign/legacy exclusions and aborts. `tests/host-procedure.integration.test.ts` injects an interruption after native callback evidence and approval persistence, recreates the host without callback replay, and verifies promotion with no human approval; it also verifies disabled-mode and unavailable-recovery behavior.

Procedure proof cites four whole safe sources: the original user task and the native failed check, intervening action and identical successful recheck. Other earlier tool results remain separate historical evidence and gain no semantic authority from their position in a window. Whole-source poisoning/credential screening occurs before deterministic segmentation and again at canonical persistence/promotion. A poisoned task or proof source prevents promotion. This refines the earlier native investigation's eight-source provenance without changing its supported outcome or claiming a causal explanation. Previously linked candidates are not automatically recreated.
