# Recovery of interrupted automatic capture

With capture, automatic promotion and canonical evidence admission enabled, each host's initialization attempts one bounded recovery batch for its current project. The shared capture coordinator and optional observation-store capability keep this behavior independent of OpenCode or Pi. Disabled modes and stores without the capability do nothing.

PostgreSQL selects at most eight already-approved canonical candidates with the current automatic policy version and outcome. It reuses the atomic consolidation pipeline: evidence, scope, conflicts and age are rechecked before semantic commit. Pending reviews, legacy approvals, unknown policy versions and other projects/providers are excluded. Concurrent restarts reuse the existing scope lock and processed ledger. Repeated recovery cannot write an old candidate over an edited or superseded memory.

Initialization waits only within the existing capture deadline so successful recovery is available before the first dispatch. Infrastructure errors or timeouts keep the host usable, report content-free diagnostics and abort the attempt. The coordinator tries once per initialization, with no new daemon or unbounded retry loop. Shutdown includes in-flight recovery within its existing deadline. PostgreSQL checks the abort signal after its bounded selection and the managed transaction checks it before semantic commit; a late query result cannot authorize promotion after cancellation.

This covers interruption after automatic approval was persisted and before its first atomic promotion. Direct capture has no durable intermediate claim. Existing CLI consolidation-run recovery remains responsible for its `consolidating` claims. Events lost before evidence persistence still require host replay; this adds no outbox. An backlog larger than eight candidates continues in later host initializations or existing maintenance commands.

`tests/capture.test.ts` verifies one attempt, disabled modes, deadline cancellation, shutdown and continued capture after failure. `tests/learning-policy.integration.test.ts` verifies current-project selection, concurrent attempts, pending/foreign/legacy exclusions and aborts. `tests/host-procedure.integration.test.ts` injects an interruption after native callback evidence and approval persistence, recreates the host without callback replay, and verifies promotion with no human approval; it also verifies disabled-mode and unavailable-recovery behavior.
