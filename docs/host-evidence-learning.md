# Host evidence learning: first vertical slice

This operational note describes the implementation in this change, not completion of the full product vision. Related issues: #43, #49, #96, #97. Keep their acceptance criteria open until verified and merged.

## Current integration

OpenCode v2's pinned SDK supplies original incoming `session.hook("prompt")` messages and completed `tool.hook("execute.after")` results with stable session/message/call IDs. The adapter sends these to the host-neutral `EvidenceCaptureCoordinator`. Admission, authorization, privacy screening, bounded queuing, PostgreSQL append, and existing capacity enforcement happen independently of semantic significance or legacy candidate capture.

Enable `evidenceAdmission.enabled: true` with an explicitly primary PostgreSQL provider. The default remains disabled. `capture.enabled` and `capture.autoPromote` still govern user-assertion candidates. When evidence admission is enabled, only successfully persisted, original unmarked user messages reach semantic capture; source provenance retains their provider/event references. Rejected, unavailable, collided, or forgotten evidence cannot fall back to legacy capture. With evidence admission disabled, legacy capture is unchanged. Observing a tool result never promotes it to semantic truth. No new storage schema or external service is introduced.

The SDK has no timestamp or verified task-completion callback. `occurredAt` records first ingestion time, preserved on replay. A prompt's `turn-completed` kind denotes the completed incoming message, not a finished assistant investigation. The pinned native `shell` tool exposes numeric `metadata.exit` and a timeout flag, although its SDK result metadata type is generic. Both exit 7 and exit 0 produce `completed` tool callbacks; the real-runtime gate checks this distinction. Neither status nor exit zero establishes a root cause or resolution of the user's task. A bounded original-prompt investigation window can now support an observed shell check-recovery procedure. Broader failed-hypothesis, root-cause and task-resolution claims still need additional evidence or review.

### Verified check recovery (Phase 5)

With capture and evidence admission enabled, OpenCode v2's production evidence-persistence callback reads at most ten scoped source rows, retaining an original user prompt and up to eight tool events. PostgreSQL ingestion order bounds this task window; equal times, an absent prompt or overflow are unsupported. The last three events must be foreground native `shell` results from distinct assistant messages: a nonzero check, a different action with exit zero, and the identical check/input with exit zero. Timeout, truncated or unknown outcomes, different execution directories, parallel same-message calls, foreign sources and failed final checks do not verify a recovery. The verifier re-admits every source and checks its hash. It executes no commands and produces no causal root-cause assertion.

`native-shell-recovery-v1` is a server-checked evidence rule, not promotion authorization. Persistence re-derives the bounded episode and validates its body and canonical references in the capture transaction. These new procedures remain pending even when legacy user-text auto-promotion is enabled. Existing review and consolidation can promote them; automatic low-risk procedure policy remains Phase 6 work. The reviewed fresh-session test therefore is not the full approval-free #96/#97 acceptance gate.

Semantic recall includes complete procedures within the existing provider/context budgets, or omits them when they cannot fit. The previous short excerpt could lose prerequisites or the final verification step. Recognition catalog summaries remain compact indexes for selecting full recall.

The window is reconstructed from durable evidence after restart. Duplicate final callbacks recover interrupted downstream capture without duplicating candidates. Asynchronous verification has a deadline and abort check before enqueueing; provider failure or shutdown does not fail an agent turn. This does not guarantee recovery of callbacks lost before persistence or introduce an outbox. Pi and OpenCode v1 have no mapping for this rule yet.

New user-assertion candidates now link to their validated canonical episode rows in both candidate storage and the ledger; capture no longer creates separate legacy observations for those events. Forget previews include secondary ledger associations while preserving existing confirmation boundaries. See [candidate lineage](candidate-lineage.md) for validation, retention, replay and legacy limitations.

PostgreSQL intentionally reconstructs no machine-local directory/worktree. Recall validates using the authorized current location while retaining the original event's project/session identity. Automatically recalled envelopes must retain their complete hash-verifiable payload: truncated search results and compacted records whose payload no longer matches the original hash are excluded. Explicit episodic search retains its existing defaults, including bounded neighbors.

## Executable evidence

- `tests/evidence-capture.test.ts`: callback mapping, privacy, scope, replay/restart/concurrent delivery, conflicting identity, bounded queue, provider failure, shutdown, and no procedure inference from completed tools.
- `tests/episodic-recall.test.ts`: opt-in continuity gating, provenance, PostgreSQL path reconstruction, hash/role/scope validation, known poisoning exclusions, independent retrieval failures.
- `tests/host-evidence.integration.test.ts`: actual PostgreSQL, plugin callback registration, Session A capture and disposal followed by fresh Session B recall, unrelated/foreign-project controls, deletion and replay suppression. Requires `REMEM_TEST_DATABASE_URL`.
- `tests/opencode-v2.e2e.mjs`: installed package and pinned real runtime, native failed/successful reads, ordinary original-user conclusion/decision/follow-up statements, fresh Session B with no previous transcript, scoped evidence injection, secret/poisoning negatives. Database CI runs this fixture.

`tests/capture.test.ts`, `tests/observation-admission.test.ts`, `tests/recall.test.ts`, `tests/postgres-provider.integration.test.ts`, and `tests/security.test.ts` additionally cover tactical-statement rejection, credential-bearing metadata keys, superseded-result exclusion before lexical/vector candidate limits and in shared recall, and bounded evidence-reference rendering. The PostgreSQL host fixture verifies stored semantic references survive plugin recreation and rejected persistence never authorizes semantic capture. Shutdown drains evidence before semantic capture because persisted user events can enqueue candidates.

These deterministic gates measure selected-content recall, false injection, provenance, conservative UTF-8 byte-based context estimates, and observed callback/dispatch timing. They do not establish model answer accuracy, verified root cause extraction, learned procedure correctness, or interrupted promotion recovery. Evidence references can become unavailable after forgetting; propagation into derived memories still requires #49. Those full #96/#97 gates depend on #49's durable lineage and verified task outcomes. Model-dependent quality evaluation should be reported separately.
