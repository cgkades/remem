# Host evidence learning: first vertical slice

This operational note describes the implementation in this change, not completion of the full product vision. Related issues: #43, #49, #96, #97. Keep their acceptance criteria open until verified and merged.

## Current integration

OpenCode v2's pinned SDK supplies original incoming `session.hook("prompt")` messages and completed `tool.hook("execute.after")` results with stable session/message/call IDs. The adapter sends these to the host-neutral `EvidenceCaptureCoordinator`. Admission, authorization, privacy screening, bounded queuing, PostgreSQL append, and existing capacity enforcement happen independently of semantic significance or legacy candidate capture.

Enable `evidenceAdmission.enabled: true` with an explicitly primary PostgreSQL provider. The default remains disabled. Legacy `capture.enabled` and `capture.autoPromote` govern user-assertion candidates separately; observing a tool result never promotes it to semantic truth. No new storage schema or external service is introduced.

| Lifecycle stage           | Current behavior and remaining gap                                                                                                                                                                                                                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Observation               | Original unmarked user messages and native tool results; metadata-bearing prompts and `memory_*` tool feedback excluded. Context dispatch is never recorded. Pi and OpenCode v1 do not yet emit this evidence stream.                                                                                                                         |
| Admission and persistence | Existing authority, project, identity, privacy, byte/depth/reference limits; content-free capture-gap diagnostics; bounded asynchronous queue. Native workspace wrappers use relative paths.                                                                                                                                                  |
| Candidate extraction      | Existing user-statement extraction remains independent. Task-resolution procedure API still needs verified host outcome wiring (#96).                                                                                                                                                                                                         |
| Consolidation and lineage | Existing review/supersession primitives retained. Durable processed candidate, evidence-to-memory edges, and atomic promotion/audit remain #49. Session/tool provenance is available for raw evidence.                                                                                                                                        |
| Planning and recall       | Opt-in continuity plans search prior-session tool evidence with no neighbors. Episodic and semantic retrieval fail independently. Ordinary unrelated prompts skip episodic search.                                                                                                                                                            |
| Injection                 | Scope and hash revalidated; historical tool data explicitly has unknown freshness and zero semantic confidence. Known poisoning patterns are excluded, alongside existing untrusted-data context boundaries. This is not a general prompt-injection detector.                                                                                 |
| Correction and forgetting | Existing preview/confirmation boundaries retained. Forgotten episode IDs cannot be replayed. Propagation into derived semantic memories requires #49 lineage.                                                                                                                                                                                 |
| Recovery                  | Duplicate callback replay survives coordinator restart; timestamp collisions from concurrent first ingestion are retried once. Graceful disposal drains within a deadline; memory outages do not fail agent turns. Uncommitted in-memory events can be lost on process termination: there is no durable outbox or guaranteed host replay yet. |

The SDK has no timestamp or verified task-completion callback. `occurredAt` records first ingestion time, preserved on replay. A prompt's `turn-completed` kind denotes the completed incoming message, not a finished assistant investigation. A tool's `completed` status establishes execution only; process exit codes, failed hypotheses, successful fixes, and verified root causes require additional evidence and task linkage before procedure learning.

PostgreSQL intentionally reconstructs no machine-local directory/worktree. Recall validates using the authorized current location while retaining the original event's project/session identity. Automatically recalled envelopes must retain their complete hash-verifiable payload: truncated search results and compacted records whose payload no longer matches the original hash are excluded. Explicit episodic search retains its existing defaults, including bounded neighbors.

## Executable evidence

- `tests/evidence-capture.test.ts`: callback mapping, privacy, scope, replay/restart/concurrent delivery, conflicting identity, bounded queue, provider failure, shutdown, and no procedure inference from completed tools.
- `tests/episodic-recall.test.ts`: opt-in continuity gating, provenance, PostgreSQL path reconstruction, hash/role/scope validation, known poisoning exclusions, independent retrieval failures.
- `tests/host-evidence.integration.test.ts`: actual PostgreSQL, plugin callback registration, Session A capture and disposal followed by fresh Session B recall, unrelated/foreign-project controls, deletion and replay suppression. Requires `REMEM_TEST_DATABASE_URL`.
- `tests/opencode-v2.e2e.mjs`: installed package and pinned real runtime, native failed/successful reads, ordinary original-user conclusion/decision/follow-up statements, fresh Session B with no previous transcript, scoped evidence injection, secret/poisoning negatives. Database CI runs this fixture.

These deterministic gates measure selected-content recall, false injection, provenance, conservative UTF-8 byte-based context estimates, and observed callback/dispatch timing. They do not establish model answer accuracy, verified root cause extraction, learned procedure correctness, obsolete-conclusion suppression, or interrupted promotion recovery. Those full #96/#97 gates depend on #49's durable lineage and verified task outcomes. Model-dependent quality evaluation should be reported separately.
