# Cross-session investigation acceptance gate

Automatic episodic retrieval validates complete historical tool envelopes before spending its existing output budget. Unsafe, current-session or oversized matches cannot consume the allowance needed by a smaller useful result. Equally matched completed outputs precede failed checks; lexical relevance still leads ordering. Explicit historical search retains its general role, neighbor and truncation behavior. `tests/episodic-budget.integration.test.ts` covers these controls against PostgreSQL. The quality scorer measures the recalled memory block separately from global catalog recognition hints.

The PostgreSQL branch of `npm run test:opencode-v2` runs the installed package inside the pinned native OpenCode v2 runtime. Set `REMEM_TEST_DATABASE_URL` to a disposable database: this fixture resets the schema. CI runs this gate with PostgreSQL/pgvector. Related issues: #96, #97, #49.

Session A investigates a missing Phoenix checkpoint. The deterministic model proposes an incorrect cache hypothesis and attempts an ineffective cache refresh. Native reads preserve a relevant workspace lookup detail while secret output is rejected and poisoning text is excluded from automatic recall. A native shell presence check fails, bounded file creation succeeds, and the identical check succeeds. The production host callbacks automatically learn this narrow verified recovery. An ordinary original-user statement supplies the observed root cause, an engineering decision and an unresolved interruption-testing follow-up. It does not invoke memory tools or approve capture. An assistant's unsupported claim that interruption recovery is fully verified never becomes verified knowledge.

The causal conclusion uses original-user authority. The tool evidence verifies only the missing-file presence-check recovery; the gate does not claim general causal extraction or application-level task completion from shell exit codes. An obsolete semantic record is seeded solely as a negative historical-state control, not as a learned answer.

Five fresh Session B sessions use a natural continuity prompt without Session A's transcript. Each must recover the current root cause, complete check/create/recheck procedure, decision, blocked follow-up and omitted episodic lookup detail. Canonical procedure references and historical uncertainty must survive injection. Superseded knowledge, false hypotheses, unsupported success claims, secrets, poisoning and unrelated project knowledge must be absent. Separate unrelated-prompt and foreign-project dispatches exercise scope isolation.

The fixture model reads the actual injected context and returns a structured answer through OpenCode. The scoring helper has negative tests for missing memory, wrong answers, truncated procedures, superseded conclusions, unsafe injection and missing provenance. This establishes deterministic transport and answer-contract correctness, not generative model quality. A pre-learning native dispatch provides the empty-knowledge baseline. Repeated fresh-session measurements report recall of required answer aspects, procedure accuracy, provenance, false injection, unsupported assertions, context bytes and host dispatch p95 latency. Context tokens are explicitly a conservative UTF-8 byte upper bound, not tokenizer output; dispatch timing includes retrieval, host and mock model work rather than isolating database latency.

Model-dependent answer quality remains a separate evaluation requiring a selected, configured host model. The deterministic fixture makes no claim about that model's reasoning, paraphrase robustness or ability to autonomously derive a root cause. Interrupted candidate promotion is covered by PostgreSQL ledger/recovery tests separately; callbacks lost before evidence persistence still have no durable outbox.
