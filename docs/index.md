# Documentation index and authority

Read intended behavior first, then verify current behavior against source and executable tests.
Do not infer missing implementation from historical plans or mark a target complete from types alone.

| Class                         | Documents                                                                                                                                                                                                                                         | Authority/use                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Normative TARGET              | [Product vision](PRODUCT-VISION.md), [target architecture](TARGET-ARCHITECTURE.md)                                                                                                                                                                | Intended product behavior and architectural boundaries                                                       |
| Accepted ADRs                 | [Decision history](adr/)                                                                                                                                                                                                                          | Accepted decisions constrain implementation; preserve history and explicitly supersede decisions when needed |
| CURRENT source snapshot       | [Current status](current-status.md)                                                                                                                                                                                                               | Verified lifecycle, source/test references, CI results and limits as of its named commit                     |
| CURRENT implementation guides | [Architecture](architecture.md), [storage](storage-architecture.md), [memory model](memory-model.md), [retrieval](retrieval-pipeline.md), [providers](provider-interface.md)                                                                      | Implemented contracts; target extensions are explicitly labeled                                              |
| Operational guides            | [Installation](installation.md), [configuration](configuration.md), [OpenCode](opencode-integration.md), [Pi](pi-integration.md), [backup/restore](backup-restore.md), [security](security-model.md), [correction review](correction-workflow.md) | Setup, authorization, failure and privacy behavior                                                           |
| Operational learning/gates    | [Host learning](host-evidence-learning.md), [lineage](candidate-lineage.md), [recovery](learning-recovery.md), [investigation gate](investigation-acceptance.md), [evaluation](evaluation.md), [embeddings](embeddings.md)                        | Scope of shipped learning, executable proof and quality limits                                               |

[Contributor guidance](../CONTRIBUTING.md) describes the engineering workflow. When documents disagree,
product vision and accepted architectural decisions define intent; current source and tests prove
implementation. Material architecture changes require a maintainer decision, not silent reinterpretation.
